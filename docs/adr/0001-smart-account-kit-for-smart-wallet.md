# Use smart-account-kit as the Smart Wallet / Policy Signer implementation

We evaluated `stellar/passkey-kit` (flat multi-signer `Signatures` map) against `stellar/smart-account-kit` (context rules + native authorization policies including spending limits, built on the audited OpenZeppelin `stellar-contracts` account) as the base for the Subscriber's Smart Wallet. We chose smart-account-kit because its policy primitives map directly onto the Policy Signer's amount/recipient/cadence rules, avoiding a hand-written policy contract; as of 2026-08-19 it is actively maintained in lockstep with passkey-kit (same last-commit date, higher repo score, zero open issues) and also ships native fee-sponsored transactions we can adopt later without changing wallets. The trade-off: the two kits are sibling SDKs with incompatible authorization models, not drop-in alternatives, so switching later means redeploying every Subscriber's Smart Wallet.
